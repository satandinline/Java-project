数据库设计

核心表结构

1. 用户表 (users)

CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  account VARCHAR(20) UNIQUE NOT NULL COMMENT '用户账号（8-10位数字，系统自动生成，永久不可修改）',
  password_hash VARCHAR(255) NOT NULL COMMENT '加密后的密码（SHA-256）',
  role ENUM('普通用户', '管理员') DEFAULT '普通用户',
  nickname VARCHAR(100) COMMENT '用户昵称（可修改）',
  avatar_path VARCHAR(255) DEFAULT '/default.jpg',
  security_question VARCHAR(255) COMMENT '自定义安全问题',
  security_answer_hash VARCHAR(255) COMMENT '安全问题答案哈希',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

设计要点：
- `account` 字段：系统自动生成的8-10位数字账号，唯一且不可修改
- `password_hash`：使用SHA-256单向哈希加密
- `role`：枚举类型，区分普通用户和管理员

2. 文化资源表 (cultural_resources)

存储爬虫抓取或用户上传的原始文化素材。

关键字段：
- `title`: 节日名称（英文）
- `content_feature_data`: JSON格式的文本内容和元数据
- `upload_user_id`: 上传用户ID（外键，级联删除时设为NULL）

3. 文化实体表 (cultural_entities)

存储从资源中提取的结构化实体信息。

关键字段：
- `entity_name`: 实体名称（中文，已清洗）
- `entity_type`: ENUM类型（'人物', '作品', '事件', '地点', '其他'）
- `description`: 详细描述（已清洗）

4. 爬虫图片表 (crawled_images)

存储爬虫抓取的图片元数据。

关键字段：
- `file_name`: 文件名（如 "8.jpg" 或 "8-1.jpg"）
- `storage_path`: 存储路径（如 "crawled_images/8.jpg"）
- `resource_id`: 关联的文化资源ID（外键，可为NULL）
- `entity_id`: 关联的文化实体ID（外键，可为NULL）
- `festival_name`: 节日名称（中文，用于快速查询）
- `tags`: JSON数组格式的标签（已清洗，移除纯数字等无关信息）

关联关系：
- 如果图片属于某个文字资源，`resource_id` 和 `entity_id` 不为NULL
- 如果图片是独立抓取的，`resource_id` 和 `entity_id` 为NULL

5. 问答会话表 (qa_sessions)

存储AIGC对话会话信息。

关键字段：
- `user_id`: 用户ID（外键，关联users表）
- `summary`: 会话摘要（自动提取的标题，不超过20字）
- `mode`: 会话模式（ENUM('text', 'image')，标识是文字AIGC还是图片AIGC）
- `created_at`: 创建时间

6. 问答消息表 (qa_messages)

存储AIGC对话中的每条消息（用户消息和AI回复）。

关键字段：
- `user_id`: 用户ID（外键，关联users表）
- `session_id`: 会话ID（外键，关联qa_sessions表）
- `user_message`: 用户输入的信息（TEXT类型）
- `ai_message`: AI的回答（TEXT类型）
- `model`: 模型类型（ENUM('text', 'image')，标识使用的模型）
- `image_url`: 图片URL（文字类型AIGC如果没有用户上传图片，使用AIGC_graph/default.jpg；图片类型AIGC存储生成的图片地址）
- `image_from_users_url`: 用户上传的图片URL（存储在AIGC_graph_from_users文件夹中，JSON格式存储多张图片）
- `retrieval_id`: 检索的资源ID列表（TEXT类型，多个ID用英文逗号分隔，用于存储RAG检索到的资源ID）
- `create_time`: 创建时间
- `timestamp`: 消息发送时间

消息保存机制：
- 用户发送消息后立即保存到数据库（ai_message为空）
- AI生成完成后使用message_id更新现有消息（UPDATE操作），避免重复插入
- 检索资源ID从RAG结果中提取并保存到retrieval_id字段

7. 用户访问日志表 (user_access_logs)

记录所有用户访问行为。

关键字段：
- `user_id`: 用户ID（外键，关联users表，包括管理员）
- `access_type`: 访问类型（'page_view'：页面访问，'aigc_text'：文字AIGC，'aigc_image'：图片AIGC，'search'：搜索，'upload'：上传等）
- `access_path`: 访问路径（如：/aigc, /search等）
- `resource_id`: 关联资源ID（可选）
- `resource_type`: 资源类型（可选）
- `access_time`: 访问时间

数据关联关系

cultural_resources (1) ──< (N) crawled_images
cultural_entities (1) ──< (N) crawled_images
users (1) ──< (N) qa_sessions
qa_sessions (1) ──< (N) qa_messages
users (1) ──< (N) user_access_logs

用户表字段说明

users表包含以下关键字段：
- `account`: 用户账号（8-10位数字，系统自动生成，永久不可修改）
- `password_hash`: 密码哈希值（SHA-256）
- `role`: 用户角色（'普通用户' 或 '管理员'）
- `nickname`: 用户昵称（可选，可修改，最多100字符）
- `signature`: 个人签名（可选，可修改，最多500字符）
- `avatar_path`: 头像路径（默认：'/default.jpg'）
- `security_question`: 自定义安全问题（用于找回密码）
- `security_answer_hash`: 安全问题答案哈希值（SHA-256）

数据库连接方式

Java后端 - JDBC连接

Java后端使用JDBC连接MySQL数据库，配置在 `DataSourceConfig.java` 中：

```java
@Configuration
public class DataSourceConfig {
    @Bean
    public DataSource dataSource() {
        DriverManagerDataSource dataSource = new DriverManagerDataSource();
        dataSource.setDriverClassName("com.mysql.cj.jdbc.Driver");
        dataSource.setUrl("jdbc:mysql://127.0.0.1:3306/java_project?...");
        dataSource.setUsername("root");
        dataSource.setPassword("password");
        return dataSource;
    }
    
    @Bean
    public JdbcTemplate jdbcTemplate(DataSource dataSource) {
        return new JdbcTemplate(dataSource);
    }
}
```

数据库配置在 `application.yml` 中：
```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://127.0.0.1:3306/java_project?useUnicode=true&characterEncoding=utf8mb4&useSSL=false&serverTimezone=Asia/Shanghai
    username: root
    password: your_password  # 请替换为实际密码
```

使用JdbcTemplate进行数据库操作：
```java
@Repository
public class UserDao {
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    public Optional<User> findById(Long id) {
        String sql = "SELECT * FROM users WHERE id = ?";
        List<User> users = jdbcTemplate.query(sql, 
                new BeanPropertyRowMapper<>(User.class), id);
        return users.isEmpty() ? Optional.empty() : Optional.of(users.get(0));
    }
}
```

Python后端 - PyMySQL连接（爬虫和AIGC使用）

Python模块（爬虫、AIGC）使用PyMySQL连接数据库，统一使用DictCursor确保返回字典格式：

```python
from pymysql.cursors import DictCursor
import pymysql

conn = pymysql.connect(
    host="127.0.0.1",
    port=3306,
    user="root",
    password="password",
    database="java_project",
    charset="utf8mb4",
    cursorclass=DictCursor  # 统一使用DictCursor，确保返回字典格式
)

# 在查询时也显式使用DictCursor
with conn.cursor(DictCursor) as cursor:
    cursor.execute("SELECT * FROM users WHERE id = %s", (user_id,))
    user = cursor.fetchone()  # 返回字典格式
```

重要说明：
- 所有Python数据库连接统一使用DictCursor，确保查询结果返回字典格式而非元组
- 在db_connection.py中已统一配置DictCursor
- 在aigc_api_server.py等模块中显式使用DictCursor确保兼容性

核心功能实现

1. 用户认证系统（Java后端）

账号生成逻辑（Java实现）

```java
public static String generateRandomAccount() {
    Random random = new Random();
    int length = random.nextInt(3) + 8; // 8-10位
    int firstDigit = random.nextInt(9) + 1; // 1-9
    StringBuilder account = new StringBuilder();
    account.append(firstDigit);
    for (int i = 1; i < length; i++) {
        account.append(random.nextInt(10));
    }
    return account.toString();
}
```

特点：
- 自动生成唯一账号
- 最多尝试100次确保唯一性
- 账号一旦生成永久不可修改

密码加密（Java实现）

使用SHA-256单向哈希算法：

```java
public static String hashPassword(String password) {
    MessageDigest digest = MessageDigest.getInstance("SHA-256");
    byte[] hash = digest.digest(password.getBytes());
    StringBuilder hexString = new StringBuilder();
    for (byte b : hash) {
        String hex = Integer.toHexString(0xff & b);
        if (hex.length() == 1) {
            hexString.append('0');
        }
        hexString.append(hex);
    }
    return hexString.toString();
}
```

2. 数据爬取系统

图片命名规则

单图片资源：
- 格式：`{序号}.jpg`（如：`8.jpg`）

多图片资源：
- 格式：`{基准序号}-{子序号}.jpg`（如：`8-1.jpg`, `8-2.jpg`, `8-3.jpg`）
- 规则：如果检测到资源有多张图片（>=2），所有图片都使用分组命名

数据清洗逻辑

中华民族资源库数据清洗：
- 移除分页信息（"上一页 下一页 总记录数"等）
- 移除日期格式（如"中元节2019-08-14"）
- 移除重复的节日名称行
- 移除纯节日名称列表项

维基百科数据清洗：
- 移除引用标记（如`[1]`、`[注 1]`）
- 移除编辑链接标记（如`[编辑]`）
- 移除分类信息

Tags清洗：
- 移除纯数字标签（URL路径中的ID）
- 移除空字符串和太短的标签（<2字符）
- 保留有意义的标签（节日名称、文化关键词等）

3. AIGC系统

RAG检索增强生成

工作流程：
1. 用户输入问题或上传图片
2. 立即保存用户消息到数据库（ai_message为空），返回message_id
3. 如果上传图片，先进行图像理解
4. 从向量数据库中检索相关文化资源
5. 从检索结果中提取资源ID列表，保存到retrieval_id字段
6. 将检索结果作为上下文，调用AI模型生成回答
7. 使用message_id更新现有消息（UPDATE操作），添加AI回答和检索资源ID

延迟加载优化：
- RAG系统和ImageAIGC系统采用延迟加载
- 只在用户首次使用时才初始化
- 显著减少系统启动时间（从19194ms降至数秒）

图像生成

工作流程：
1. 用户输入提示词或上传参考图片
2. 立即保存用户消息到数据库（ai_message为空），返回message_id
3. 如果上传图片，先进行图像理解（使用RAG系统）
4. 如果没有提示词，使用RAG系统自动生成故事
5. 调用图像生成API（Huoshan模型）
6. 使用message_id更新现有消息（UPDATE操作），添加AI回答和生成的图片URL
7. 保存生成的图片到本地（AIGC_graph文件夹）和数据库

用户上传图片处理：
- 用户上传的AIGC图片统一存入AIGC_graph_from_users文件夹
- 文件命名格式：用户账号-上传时间.扩展名
- 存储逻辑与uploads文件夹一致
- 如果没有上传图片，使用AIGC_graph/default.jpg作为默认图片

4. 资源上传系统

文本资源上传：
- 支持两种方式：直接输入文本内容或上传文件
- 文件格式限制：仅支持Word文档（.doc, .docx）或PDF（.pdf）
- 自动解析文件内容：使用python-docx解析Word文档，PyPDF2解析PDF文档
- 完整文本内容保存在content_feature_data.content_full中，用于AI标注

图像资源上传：
- 文件格式限制：仅支持JPG（.jpg）或PNG（.png）
- 文件存储路径保存在storage_path字段中（相对于项目根目录）

用户标注：
- 用户可在上传时进行标注，标注格式与AI标注、人工标注完全一致
- 标注字段包括：实体名称、实体类型、描述、来源、时期年代、地理坐标、文化区域、风格特征、文化价值、相关图像链接、数字资源链接
- 如果用户提供了标注，会立即保存为人工标注记录，同时仍会触发AI标注

5. 标注任务系统

任务状态流转：
- 待标注：任务已创建，AI尚未开始
- AI标注中：AI正在处理资源
- AI标注完成：AI标注结果已保存
- 已完成：人工标注完成（包括上传时自标注或任务页上的人工编辑）

资源来源支持：
- cultural_resources：爬虫抓取的资源
- cultural_resources_from_user：用户上传的资源
- AIGC_cultural_resources：AIGC生成的资源

权限控制：
- 普通用户：只能看到自己上传的资源对应的标注任务
- 管理员：可以看到所有标注任务（包括爬虫、用户上传、AIGC生成）

资源展示：
- 文本资源：在标注任务中显示文本内容预览（content_preview）
- 图像资源：在标注任务中显示图片（通过storage_path或content_feature_data获取文件路径）
- 前端通过/api/uploads/<filename>接口访问上传的文件

AI标注自动触发：
- 检测到用户上传资源后，自动创建AI标注任务
- 对于文本资源，使用完整文本内容（content_full）进行AI标注
- 对于图像资源，使用图片路径进行视觉理解标注

6. 数据关联系统

文字资源与图片的关联：
- 爬虫先保存文字资源，获取`resource_id`和`entity_id`
- 保存图片时，将`resource_id`和`entity_id`写入`crawled_images`表
- 如果只有图片没有文字，图片的`resource_id`和`entity_id`为NULL

用户上传、AIGC生成与爬虫抓取的统一逻辑：
- 所有资源类型（爬虫、用户上传、AIGC生成）都通过resource_id关联到cultural_resources表
- 图像资源统一存储在crawled_images表中，通过resource_id关联
- 标注任务通过resource_source字段区分资源来源，支持三种来源的统一管理

查询优化：
- 通过`festival_name`字段快速查询某个节日的所有图片
- 通过`resource_id`查询某个文字资源的所有图片
- 通过`entity_id`查询某个文化实体的所有图片

5. 前端设置页面系统

设置页面采用列表式布局（类似QQ设置），包含以下功能：

账号显示：
- 仅显示，不可修改
- 显示用户的8-10位数字账号

昵称管理：
- 可点击进入修改界面
- 下方显示当前昵称
- 支持最多100个字符
- API: POST /api/auth/update-nickname

个人签名管理：
- 可点击进入设置界面
- 下方显示当前签名（未设置时显示"未设置"）
- 支持最多500个字符
- 使用textarea输入框，支持多行文本
- 显示字符计数（已输入/500）
- API: POST /api/auth/update-signature

密码管理：
- 可点击进入修改界面
- 支持两种验证方式：
  - 原密码验证
  - 二级密码验证（如果已设置安全问题）
- API: POST /api/auth/change-password

二级问题管理：
- 可点击进入设置界面
- 如果已设置，需要先验证原答案
- 支持设置新问题和新答案
- API: POST /api/auth/change-security-question

头像管理：
- 方式一：通过设置列表进入
- 方式二：直接点击页面右上角的用户头像
- 支持上传新头像（自动裁剪到200x200像素）
- 支持使用默认头像
- API: POST /api/auth/change-avatar

账号注销：
- 位于设置列表最底部
- 红色文字，表示危险操作
- 需要输入密码确认
- 注销后账号永久删除，无法恢复
- API: POST /api/auth/delete-account

技术实现：
- 使用Vue 3 Composition API
- 使用ref管理状态（settingsTab, fromAvatarClick等）
- 条件渲染显示不同的设置面板
- 使用sessionStorage保存用户信息（关闭浏览器后需要重新登录）
- 所有API调用都包含X-User-Id请求头

部署与运维

环境要求

- Java: 最新LTS版本（推荐Java 17或21）
- Maven 3.6 或更高版本
- MySQL 8.0 或更高版本（推荐使用最新版本）
- Node.js 16+（前端）
- Python 3.7+（可选，用于爬虫和AIGC功能）
- 至少2GB内存

部署步骤

1. 安装Java和Maven：
   - 下载并安装最新LTS版本的JDK（推荐Java 17或21）
   - 下载并安装Maven 3.6+
   - 配置JAVA_HOME和MAVEN_HOME环境变量

2. 安装其他依赖：
   python install_dependencies.py
   （这会安装Python和Node.js依赖）

3. 初始化数据库：
   python database_files/run_init_schema.py

4. 配置环境变量：
   创建`.env`文件，配置数据库和API密钥
   
   数据库配置在 `backend/src/main/resources/application.yml` 中：
   ```yaml
   spring:
     datasource:
       url: jdbc:mysql://127.0.0.1:3306/java_project?...
       username: root
       password: your_password
   ```

5. 启动Java后端：
   cd backend
   mvn spring-boot:run
   
   或使用启动脚本：
   # Windows
   cd backend
   start_backend.bat
   
   # Linux/Mac
   cd backend
   chmod +x start_backend.sh
   ./start_backend.sh

6. 启动前端：
   cd FrontEnd
   npm run dev

7. （可选）启动Python AIGC服务（如果需要AI功能）：
   python AIGC/aigc_api_server.py

监控与日志

- 访问日志：存储在`user_access_logs`表
- 错误日志：
  - Java后端：控制台输出，可通过logback配置日志文件
  - Python服务：控制台输出
- 数据统计：管理员数据大屏
- 日志级别配置：在`application.yml`中配置

备份策略

1. 数据库备份：
   - 定期备份MySQL数据库
   - 建议每日备份

2. 文件备份：
   - `crawled_images/`：爬虫图片
   - `AIGC_graph/`：AIGC生成图片
   - `FrontEnd/public/`：用户头像

性能优化建议

1. 数据库优化：
   - 定期清理历史日志数据
   - 优化慢查询
   - 使用连接池

2. 缓存策略：
   - 考虑使用Redis缓存热点数据
   - 静态资源使用CDN

3. 图片优化：
   - 压缩大图片
   - 使用WebP格式
   - 实现图片懒加载

常见问题排查

1. 数据库连接失败

检查项：
- MySQL服务是否运行（MySQL 8.0+）
- `backend/src/main/resources/application.yml`中的数据库配置是否正确
- 数据库用户权限
- JDBC驱动是否正确加载
- 检查MySQL版本是否为8.0或更高版本

2. API请求失败或页面加载缓慢

检查项：
- Java后端服务是否运行（端口8000）
  - 检查：`cd backend && mvn spring-boot:run`
  - 查看控制台是否有启动错误
  - 确认后端服务正常启动后再访问前端
- Python AIGC服务是否运行（端口7200，如果使用AIGC功能）
  - 检查：`python AIGC/aigc_api_server.py`
  - 查看控制台是否有启动错误（注意Unicode编码错误）
  - 确认服务正常启动后再使用AIGC功能
- 前端代理配置是否正确（`FrontEnd/vite.config.js`）
  - 确认代理目标端口为7200（Python后端）或8000（Java后端）
- 前端请求超时设置（默认10秒）
- 查看浏览器控制台是否有错误信息
- 查看后端日志
- 如果后端服务未运行，前端会在10秒后显示超时错误

3. 图片无法显示

检查项：
- 图片文件是否存在
- 文件路径是否正确
- WebConfig中的静态资源路径配置是否正确
- 文件权限设置

4. AIGC功能异常

检查项：
- Python AIGC服务是否运行（如果使用AI功能，端口7200）
- AI模型API密钥配置
- 网络连接是否正常
- 查看错误日志
- 如果看到"cannot access local variable 'rag_system'"，说明变量作用域问题，已修复（在函数开始处初始化rag_system变量）
- 如果看到"JSON.parse: unexpected end of data"，可能是数据库查询返回格式问题，已修复（统一使用DictCursor）
- 如果看到重复的用户消息，说明消息保存逻辑问题，已修复为UPDATE机制
- 检查AIGC_graph_from_users文件夹是否存在（用户上传图片存储位置）
- 检查retrieval_id字段是否正确保存（从RAG检索结果中提取资源ID）

5. Maven依赖下载失败

检查项：
- Maven配置是否正确
- 网络连接是否正常
- 可以配置Maven镜像加速下载
- 确认Java版本是否为最新LTS版本（推荐Java 17或21）

6. 页面无法打开或一直加载

检查项：
- 确认Java后端服务已启动（端口8000）
  - 运行 `cd backend && mvn spring-boot:run`
  - 检查控制台是否有启动成功信息
- 确认Python AIGC服务已启动（端口7200，如果使用AIGC功能）
  - 运行 `python AIGC/aigc_api_server.py`
  - 检查控制台是否有启动成功信息
  - 注意：如果看到UnicodeEncodeError，说明代码中使用了Windows GBK编码不支持的字符，已修复
- 检查浏览器控制台错误信息（F12）
  - 如果看到 "Content process isn't responsive"，可能是浏览器资源问题
  - 如果看到 "请求超时"，说明后端服务未运行
  - 如果看到 "ECONNREFUSED"，说明后端服务未启动或端口配置错误
- 清除浏览器缓存（Ctrl+Shift+Delete）
- 检查前端服务是否正常运行（端口5173）
- 确认网络连接正常
- 如果后端服务未运行，页面会在10秒后显示超时错误提示
- 检查端口占用情况：
  - Java后端：`netstat -ano | findstr :8000`
  - Python后端：`netstat -ano | findstr :7200`
- 尝试使用隐私/无痕模式打开页面
- 详细排查步骤请参考 `FrontEnd/TROUBLESHOOTING.md`
