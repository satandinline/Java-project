一、项目概述
================================================================================

1.1 项目简介
------------
公共文化资源管理系统是一个基于AI的综合性文化资源管理平台，支持文化资源的
爬取、存储、检索、生成和管理。系统采用前后端分离架构，使用Python Flask
作为后端API服务器，Vue.js 3作为前端框架。

1.2 核心功能
------------
- 用户管理和认证系统
- 文化资源爬取（民族文化资源库、维基百科）
- AIGC内容生成（文字和图片）
- 图文互搜功能
- 资源上传和审核
- 标注任务管理
- 用户评分和评论系统

1.3 技术栈
----------
后端：
- Python 3.7+
- Flask 2.3.0+ (Web框架)
- PyMySQL (MySQL数据库连接)
- LangChain 0.3.26+ (RAG和AIGC核心)
- ChromaDB (向量数据库)
- Pillow (图像处理)
- NumPy (数值计算)

前端：
- Vue.js 3 (Composition API)
- Vite (构建工具)
- Vue Router 4 (路由管理)

数据库：
- MySQL 5.7+
- 17个数据表
- 支持视图和索引

AI模型：
- 文字AIGC：通义千问（Tongyi）
- 图片AIGC：火山引擎Seedream（Huoshan）
- 备选：OpenAI GPT

2.2 数据流向
------------
1. 爬虫数据：
   - 文字数据 → cultural_resources（title=节日名称）+ cultural_entities（entity_name=资源名称）
   - 图片数据 → crawled_images

2. AIGC生成数据：
   - 文字数据 → AIGC_cultural_resources（title=节日名称）+ AIGC_cultural_entities（entity_name=资源名称）
   - 图片数据 → AIGC_graph

3. 用户上传数据：
   - 待审核数据 → cultural_resources_from_user
   - 审核通过后 → cultural_resources

4. AIGC对话记录：
   - 会话信息 → qa_sessions
   - 对话消息 → qa_messages

5. 标注任务：
   - 标注任务 → annotation_tasks（通过resource_source字段关联不同的资源表）
   - 标注记录 → annotation_records（使用扁平化字段结构）

6. 用户评分和评论：
   - 评分数据 → user_ratings
   - 评论数据 → user_comments
   - 回复数据 → comment_replies

三、数据库设计
================================================================================

3.1 数据库概述
--------------
- 数据库名称：java_project
- 字符集：utf8mb4
- 表数量：17个
- 视图数量：17个（每个表对应一个只读视图）

3.2 核心表结构
--------------

1. users（用户表）
   - id: 主键
   - username: 用户名（唯一）
   - password_hash: 密码哈希值（SHA-256）
   - role: 角色（普通用户/管理员）
   - nickname: 用户昵称
   - avatar_path: 头像路径
   - security_question: 安全问题
   - security_answer_hash: 安全问题答案哈希值

2. cultural_resources（文化资源表）
   - id: 主键
   - title: 节日名称
   - resource_type: 资源类型
   - file_format: 文件格式
   - source_from: 数据来源
   - source_url: 原始URL
   - content_feature_data: 内容数据（JSON格式）
   - upload_user_id: 上传用户ID（外键，可NULL）
   - ai_review_status: AI审核状态
   - manual_review_status: 人工审核状态

3. cultural_entities（文化实体表）
   - id: 主键
   - entity_name: 实体名称
   - entity_type: 实体类型（ENUM: 人物/作品/事件/地点/其他）
   - description: 描述
   - source: 来源
   - period_era: 时期年代
   - geo_coordinates: 地理坐标
   - cultural_region: 文化区域
   - style_features: 风格特征
   - cultural_value: 文化价值
   - related_images_url: 相关图像链接
   - digital_resource_link: 数字资源链接
   - 全文索引：entity_name, description

4. entity_relationships（实体关系表）
   - id: 主键
   - source_entity_id: 源实体ID（外键）
   - target_entity_id: 目标实体ID（外键）
   - relationship_type: 关系类型
   - relationship_strength: 关系强度
   - relationship_evidence: 关系证据
   - spatiotemporal_constraint: 时空约束
   - confidence_score: 置信度评分

5. user_behavior_logs（用户行为日志表）
   - id: 主键
   - user_id: 用户ID（外键）
   - behavior_type: 行为类型（ENUM: 检索/交互/生成/标注）
   - content: 行为内容
   - timestamp: 时间戳

6. qa_sessions（问答会话表）
   - id: 主键
   - user_id: 用户ID（外键）
   - created_at: 创建时间
   - summary: 会话摘要

7. qa_messages（问答消息表）
   - id: 主键
   - user_id: 用户ID（外键）
   - session_id: 会话ID（外键）
   - create_time: 创建时间
   - user_message: 用户输入的信息
   - ai_message: AI的回答
   - user_feedback: 用户反馈
   - timestamp: 时间戳
   - model: 模型类型（ENUM: text/image）
   - image_url: 图片URL（图片AIGC时存储）
   - image_from_users_url: 用户上传的图片URL

8. annotation_tasks（标注任务表）
   - id: 主键
   - resource_id: 关联的资源ID
   - resource_source: 资源来源（ENUM: cultural_resources/cultural_resources_from_user）
   - task_type: 任务体系（ENUM: 实体/质量/语义）
   - annotation_method: 标注方式（ENUM: ai/manual）
   - status: 任务状态
   - required_annotators: 需要的标注人数

9. annotation_records（标注记录表）
   - id: 主键
   - task_id: 任务ID（外键）
   - annotator_id: 标注者ID（外键）
   - annotation_data: 标注数据（JSON格式，保留兼容性）
   - annotation_source: 标注来源（ENUM: ai/manual）
   - is_expert_reviewed: 是否经过专家审核
   - reviewer_id: 审核专家ID（外键，可NULL）
   - created_at: 标注提交时间
   - is_latest: 是否为最新标注结果
   - create_time: 标注时间
   - 扁平化字段（新增）：
     * entity_name: 实体名称
     * entity_type: 实体类型（ENUM: 人物/作品/事件/地点/其他）
     * description: 描述
     * source: 来源
     * period_era: 时期年代
     * geo_coordinates: 地理坐标
     * cultural_region: 文化区域
     * style_features: 风格特征
     * cultural_value: 文化价值
     * related_images_url: 相关图像链接
     * digital_resource_link: 数字资源链接

10. cultural_resources_from_user（用户上传资源表）
    - id: 主键
    - user_id: 上传用户ID（外键）
    - title: 节日
    - resource_type: 资源类型
    - file_format: 文件格式
    - content_feature_data: 内容数据（JSON格式，包含文件名、用户名、上传时间等信息）
    - content_hash: 内容哈希值（SHA-256，用于查重）
    - ai_review_status: AI审核状态（ENUM: pending/passed/failed）
    - manual_review_status: 人工审核状态（ENUM: pending/passed/failed）
    - upload_time: 上传时间
    - review_notes: 审核备注

11. AIGC_cultural_resources（AIGC文化资源表）
    - id: 主键
    - title: 节日名称
    - resource_type: 资源类型
    - file_format: 文件格式
    - source_from: 数据来源（AIGC模型名称）
    - source_url: 原始URL链接
    - content_feature_data: 内容数据
    - version: 版本号
    - created_at: 创建时间
    - updated_at: 更新时间

12. AIGC_graph（AIGC生成图像表）
    - id: 主键
    - file_name: 文件名
    - storage_path: 存储路径（唯一）
    - dimensions: 尺寸
    - upload_time: 上传时间
    - tags: 标签（JSON数组格式）

13. crawled_images（爬虫抓取图像表）
    - id: 主键
    - file_name: 文件名
    - storage_path: 存储路径（唯一）
    - dimensions: 尺寸
    - crawl_time: 抓取时间
    - tags: 标签（JSON数组格式）

14. AIGC_cultural_entities（AIGC文化实体表）
    - id: 主键
    - entity_name: 实体名称
    - entity_type: 实体类型（ENUM: 人物/作品/事件/地点/其他）
    - description: 描述
    - source: 来源
    - period_era: 时期年代
    - geo_coordinates: 地理坐标
    - cultural_region: 文化区域
    - style_features: 风格特征
    - cultural_value: 文化价值
    - related_images_url: 相关图像链接
    - digital_resource_link: 数字资源链接
    - 全文索引：entity_name, description

15. user_ratings（用户评分表）
    - id: 主键
    - resource_id: 关联文化资源ID（外键）
    - user_id: 关联用户ID（外键）
    - rating: 评分（1-5分）
    - rating_dimension: 评分维度（overall/accuracy/usefulness/completeness）
    - rated_at: 评分时间
    - 唯一约束：user_id, resource_id, rating_dimension

16. user_comments（用户评论表）
    - id: 主键
    - resource_id: 关联文化资源ID（外键）
    - user_id: 关联用户ID（外键）
    - comment_content: 评论内容
    - comment_status: 评论状态（pending/approved/rejected）
    - is_academic_discussion: 是否学术讨论
    - reviewer_id: 审核人ID（外键，可NULL）
    - reviewed_at: 审核时间
    - created_at: 评论创建时间
    - updated_at: 评论更新时间

17. comment_replies（评论回复表）
    - id: 主键
    - comment_id: 关联评论ID（外键）
    - reply_user_id: 回复用户ID（外键）
    - reply_content: 回复内容
    - created_at: 回复创建时间

3.3 视图
--------
系统为每个表创建了对应的只读视图（v_表名），便于统一查询与权限控制。

3.4 索引策略
------------
- 主键自动创建聚簇索引
- 外键字段创建索引
- 全文索引：cultural_entities和AIGC_cultural_entities的entity_name和description字段
- 唯一索引：users.username, cultural_resources.source_url, user_ratings复合唯一索引等

================================================================================
五、关键技术实现
================================================================================

5.1 文件上传处理
----------------
流程：
1. 接收文件数据
2. 生成唯一文件名（用户名-日期-时间格式）
3. 保存文件到uploads/目录
4. 计算文件哈希值（SHA-256）
5. 查重校验
6. 提取节日名称（从文件名或内容）
7. 保存到cultural_resources_from_user表
8. 创建标注任务
9. 触发AI标注（后台线程）

文件命名规则：
- 格式：{用户名}-{YYYY-MM-DD}-{HH-MM-SS}.扩展名
- 如果文件已存在，添加序号：{用户名}-{日期}-{时间}-{序号}.扩展名
- 用户名中的特殊字符会被替换为下划线

5.2 标注系统实现
----------------
标注记录表结构：
- 保留annotation_data字段（JSON格式）用于兼容旧数据
- 新增扁平化字段，符合cultural_entities表结构标准
- 支持AI标注和人工标注
- 支持专家审核

标注流程：
1. 用户上传资源 → 自动创建标注任务
2. AI自动标注 → 保存到annotation_records（使用扁平化字段）
3. 用户可编辑标注 → 更新annotation_records
4. 管理员审核 → 标记is_expert_reviewed
5. 审核通过 → 数据迁移到cultural_entities和cultural_resources

5.3 RAG检索增强生成
-------------------
实现流程：
1. 用户输入问题
2. 文本分割和向量化
3. 向量数据库检索（相似度检索）
4. 关键词检索（补充）
5. 构建上下文
6. 调用AI模型生成回答
7. 返回结果并保存对话记录

向量数据库：
- chroma_db: 文本向量数据库
- chroma_db_image: 图像向量数据库
- chroma_db_web: Web向量数据库
- chroma_db_annotation: 标注向量数据库

5.4 图片生成流程
----------------
实现流程：
1. 接收用户输入（文字提示词或图片）
2. 如果上传图片，使用图片理解逻辑分析图片内容
3. 如果没有文字提示，自动生成故事
4. 调用图片生成API（火山引擎Seedream）
5. 保存生成的图片到AIGC_graph/目录
6. 保存元数据到AIGC_graph表
7. 返回图片URL

5.5 用户认证和安全
------------------
密码加密：
- 算法：SHA-256单向哈希
- 存储：只存储哈希值，不存储明文密码
- 验证：登录时对输入密码进行哈希后比较

安全问题：
- 支持自定义安全问题
- 安全问题答案也使用SHA-256加密
- 用于找回密码功能

会话管理：
- 使用Flask的session机制
- 前端使用localStorage存储用户信息
- 自动验证用户信息有效性

5.6 数据迁移机制
----------------
标注审核通过后的数据迁移：
1. 从annotation_records获取标注数据（扁平化字段）
2. 根据任务类型迁移到不同表：
   - 实体类型 → cultural_entities表
3. 如果资源来源是cultural_resources_from_user：
   - 迁移资源到cultural_resources表
   - 更新原资源表的审核状态
4. 如果是图像资源：
   - 迁移到crawled_images表
5. 更新任务状态为"已完成"

六、API接口规范
================================================================================

6.1 认证相关接口
----------------
POST /api/register
- 功能：用户注册
- 参数：username, password, nickname(可选), avatar(可选), security_question(可选), security_answer(可选)
- 返回：注册结果

POST /api/login
- 功能：用户登录
- 参数：username, password
- 返回：登录结果和用户信息

POST /api/change-password
- 功能：修改密码
- 请求头：X-User-Id
- 参数：old_password, new_password
- 返回：修改结果

POST /api/forgot-password
- 功能：忘记密码
- 参数：username, security_answer, new_password
- 返回：重置结果

6.2 AIGC相关接口
----------------
POST /api/aigc/chat
- 功能：AIGC聊天（文字或图片生成）
- 请求头：X-User-Id
- 参数：mode(text/image), query(可选), images(可选), session_id(可选), stream(可选)
- 返回：生成结果（流式或JSON格式）

POST /api/aigc/sessions
- 功能：创建新会话
- 请求头：X-User-Id
- 参数：summary(可选)
- 返回：会话ID

GET /api/aigc/sessions
- 功能：获取会话列表
- 请求头：X-User-Id
- 查询参数：user_id
- 返回：会话列表

GET /api/aigc/sessions/{session_id}/messages
- 功能：获取会话消息
- 请求头：X-User-Id
- 返回：消息列表

DELETE /api/aigc/sessions/{session_id}
- 功能：删除单个会话
- 请求头：X-User-Id
- 返回：删除结果

DELETE /api/aigc/sessions/batch
- 功能：批量删除会话
- 请求头：X-User-Id
- 参数：session_ids（数组）
- 返回：删除结果

DELETE /api/aigc/sessions/all
- 功能：删除所有会话
- 请求头：X-User-Id
- 返回：删除结果

6.3 标注相关接口
----------------
GET /api/annotation/tasks
- 功能：获取标注任务列表
- 请求头：X-User-Id
- 查询参数：user_id, status(可选)
- 返回：任务列表（包含文件名、用户名、上传时间等信息）

GET /api/annotation/tasks/{task_id}/details
- 功能：获取标注详情
- 请求头：X-User-Id
- 返回：标注详情（使用扁平化字段结构）

PUT /api/annotation/tasks/{task_id}
- 功能：更新标注
- 请求头：X-User-Id
- 参数：支持新格式（扁平化字段）和旧格式（entities数组）
- 返回：更新结果

POST /api/annotation/tasks/{task_id}/approve
- 功能：审核通过标注并迁移数据
- 请求头：X-User-Id（必须是管理员）
- 返回：迁移结果

POST /api/annotation/tasks/{task_id}/reject
- 功能：驳回标注
- 请求头：X-User-Id（必须是管理员）
- 参数：reason（驳回原因）
- 返回：驳回结果

6.4 资源相关接口
----------------
GET /api/home/resources
- 功能：获取资源列表
- 查询参数：page, page_size
- 返回：资源列表和分页信息

POST /api/upload
- 功能：上传资源
- 请求头：X-User-Id, Content-Type: multipart/form-data
- 参数：file, resource_type
- 返回：上传结果

6.5 搜索相关接口
----------------
POST /api/search/text-to-image
- 功能：文本搜图片
- 参数：query（搜索关键词）
- 返回：匹配的图片列表

POST /api/search/image-to-text
- 功能：图片搜文本
- 参数：image（图片文件）
- 返回：匹配的文本列表

七、部署和配置
================================================================================

7.1 环境要求
------------
- Python 3.7+
- Node.js 16+
- MySQL 5.7+
- 至少4GB内存（推荐8GB）

7.2 安装步骤
------------
1. 克隆项目
2. 运行 install_dependencies.py 安装所有依赖
3. 配置数据库（运行 database_files/run_init_schema.py）
4. 配置环境变量（.env文件）
5. 启动服务（使用 start_dev.bat 或 start_dev.sh）

7.3 环境变量配置
----------------
必需配置：
- MYSQL_HOST: 数据库主机（默认：127.0.0.1）
- MYSQL_PORT: 数据库端口（默认：3306）
- MYSQL_USER: 数据库用户（默认：root）
- MYSQL_PASSWORD: 数据库密码
- MYSQL_DB: 数据库名称（默认：java_project）

AI模型配置（至少配置一个）：
- DASHSCOPE_API_KEY: 阿里云通义千问API密钥
- OPENAI_API_KEY: OpenAI API密钥（备选）
- VOLC_SEEDREAM_API_KEY: 火山引擎Seedream API密钥

7.4 启动方式
------------
方式一：一键启动（推荐）
- Windows: start_dev.bat
- Linux/Mac: ./start_dev.sh

方式二：分别启动
- 前端：cd FrontEnd && npm run dev
- 后端：python AIGC/aigc_api_server.py

7.5 端口配置
------------
- 前端开发服务器：5173
- 后端API服务器：8000
- 前端通过Vite代理访问后端（/api/* → http://localhost:8000）

八、安全考虑
================================================================================

8.1 密码安全
------------
- 使用SHA-256单向哈希算法
- 不存储明文密码
- 登录时进行哈希比较

8.2 数据隔离
------------
- 不同用户使用不同的数据库连接（通过user_id）
- 普通用户只能看到自己上传的资源
- 管理员可以看到所有资源

8.3 文件安全
------------
- 文件上传时进行哈希查重
- 文件名使用安全格式（清理特殊字符）
- 文件路径验证（防止路径遍历攻击）

8.4 API安全
------------
- 使用请求头X-User-Id进行用户身份验证
- 敏感操作需要管理员权限
- 输入验证和SQL注入防护

11.1 常见问题
-------------
1. 数据库连接失败
   - 检查MySQL服务是否运行
   - 验证环境变量配置
   - 检查数据库用户权限

2. API请求失败
   - 检查后端服务器是否运行
   - 验证API密钥配置
   - 查看后端日志

3. 图片无法显示
   - 确认文件路径正确
   - 检查文件权限
   - 验证静态文件服务配置

4. 前端页面空白
   - 检查浏览器控制台错误
   - 确认后端API服务器运行正常
   - 检查路由配置

-------------
- 后端日志：aigc_logs/aigc.log
