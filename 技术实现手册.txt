数据库设计

核心表结构

1. 用户表 (users)

CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  account VARCHAR(20) UNIQUE NOT NULL COMMENT '用户账号（8-10位数字，系统自动生成，永久不可修改）',
  password_hash VARCHAR(255) NOT NULL COMMENT '加密后的密码（SHA-256）',
  role ENUM('普通用户', '管理员') DEFAULT '普通用户',
  nickname VARCHAR(100) COMMENT '用户昵称（可修改）',
  avatar_path VARCHAR(255) DEFAULT '/default.jpg',
  security_question VARCHAR(255) COMMENT '自定义安全问题',
  security_answer_hash VARCHAR(255) COMMENT '安全问题答案哈希',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

设计要点：
- `account` 字段：系统自动生成的8-10位数字账号，唯一且不可修改
- `password_hash`：使用SHA-256单向哈希加密
- `role`：枚举类型，区分普通用户和管理员

2. 文化资源表 (cultural_resources)

存储爬虫抓取或用户上传的原始文化素材。

关键字段：
- `title`: 节日名称（英文）
- `content_feature_data`: JSON格式的文本内容和元数据
- `upload_user_id`: 上传用户ID（外键，级联删除时设为NULL）

3. 文化实体表 (cultural_entities)

存储从资源中提取的结构化实体信息。

关键字段：
- `entity_name`: 实体名称（中文，已清洗）
- `entity_type`: ENUM类型（'人物', '作品', '事件', '地点', '其他'）
- `description`: 详细描述（已清洗）

4. 爬虫图片表 (crawled_images)

存储爬虫抓取的图片元数据。

关键字段：
- `file_name`: 文件名（如 "8.jpg" 或 "8-1.jpg"）
- `storage_path`: 存储路径（如 "crawled_images/8.jpg"）
- `resource_id`: 关联的文化资源ID（外键，可为NULL）
- `entity_id`: 关联的文化实体ID（外键，可为NULL）
- `festival_name`: 节日名称（中文，用于快速查询）
- `tags`: JSON数组格式的标签（已清洗，移除纯数字等无关信息）

关联关系：
- 如果图片属于某个文字资源，`resource_id` 和 `entity_id` 不为NULL
- 如果图片是独立抓取的，`resource_id` 和 `entity_id` 为NULL

5. 用户访问日志表 (user_access_logs)

记录所有用户访问行为。

关键字段：
- `user_id`: 用户ID（可为NULL，表示未登录访问）
- `access_type`: 访问类型（'page_view', 'aigc_text', 'aigc_image', 'search', 'upload'等）
- `access_detail`: JSON格式的访问详情
- `ip_address`: 用户IP地址
- `user_agent`: 用户代理字符串

数据关联关系

cultural_resources (1) ──< (N) crawled_images
cultural_entities (1) ──< (N) crawled_images
users (1) ──< (N) qa_sessions
qa_sessions (1) ──< (N) qa_messages
users (1) ──< (N) user_access_logs

核心功能实现

1. 用户认证系统

账号生成逻辑

def _generate_random_account(self) -> str:
    """生成随机账号（8-10位数字字符串）"""
    import random
    length = random.randint(8, 10)
    # 生成8-10位数字字符串，第一位不能是0
    first_digit = random.randint(1, 9)
    rest_digits = ''.join([str(random.randint(0, 9)) for _ in range(length - 1)])
    return str(first_digit) + rest_digits

特点：
- 自动生成唯一账号
- 最多尝试100次确保唯一性
- 账号一旦生成永久不可修改

密码加密

使用SHA-256单向哈希算法：

def _hash_password(self, password: str) -> str:
    return hashlib.sha256(password.encode()).hexdigest()

2. 数据爬取系统

图片命名规则

单图片资源：
- 格式：`{序号}.jpg`（如：`8.jpg`）

多图片资源：
- 格式：`{基准序号}-{子序号}.jpg`（如：`8-1.jpg`, `8-2.jpg`, `8-3.jpg`）
- 规则：如果检测到资源有多张图片（>=2），所有图片都使用分组命名

数据清洗逻辑

中华民族资源库数据清洗：
- 移除分页信息（"上一页 下一页 总记录数"等）
- 移除日期格式（如"中元节2019-08-14"）
- 移除重复的节日名称行
- 移除纯节日名称列表项

维基百科数据清洗：
- 移除引用标记（如`[1]`、`[注 1]`）
- 移除编辑链接标记（如`[编辑]`）
- 移除分类信息

Tags清洗：
- 移除纯数字标签（URL路径中的ID）
- 移除空字符串和太短的标签（<2字符）
- 保留有意义的标签（节日名称、文化关键词等）

3. AIGC系统

RAG检索增强生成

工作流程：
1. 用户输入问题或上传图片
2. 如果上传图片，先进行图像理解
3. 从向量数据库中检索相关文化资源
4. 将检索结果作为上下文，调用AI模型生成回答
5. 保存对话记录到数据库

延迟加载优化：
- RAG系统和ImageAIGC系统采用延迟加载
- 只在用户首次使用时才初始化
- 显著减少系统启动时间（从19194ms降至数秒）

图像生成

工作流程：
1. 用户输入提示词或上传参考图片
2. 如果没有提示词，自动生成故事
3. 调用图像生成API（Huoshan模型）
4. 保存生成的图片到本地和数据库

4. 数据关联系统

文字资源与图片的关联：
- 爬虫先保存文字资源，获取`resource_id`和`entity_id`
- 保存图片时，将`resource_id`和`entity_id`写入`crawled_images`表
- 如果只有图片没有文字，图片的`resource_id`和`entity_id`为NULL

查询优化：
- 通过`festival_name`字段快速查询某个节日的所有图片
- 通过`resource_id`查询某个文字资源的所有图片
- 通过`entity_id`查询某个文化实体的所有图片

代码规范与最佳实践

Python代码规范

1. 命名规范：
   - 类名：大驼峰（`AuthSystem`）
   - 函数名：小写下划线（`get_user_by_id`）
   - 私有方法：单下划线前缀（`_hash_password`）
   - 常量：全大写下划线（`MAX_RETRY_COUNT`）

2. 错误处理：
   - 使用try-except捕获异常
   - 记录详细的错误日志
   - 返回用户友好的错误消息

3. 数据库操作：
   - 使用上下文管理器（`with conn.cursor()`）
   - 及时提交或回滚事务
   - 关闭数据库连接

4. 代码复用：
   - 避免重复代码
   - 提取公共函数
   - 使用配置常量而非硬编码

Vue.js代码规范

1. 组件结构：
   - 使用Composition API
   - `<script setup>` 语法
   - 单一职责原则

2. 状态管理：
   - 使用`ref`和`reactive`管理状态
   - 避免过度使用全局状态
   - 合理使用`computed`和`watch`

3. API调用：
   - 统一错误处理
   - 显示加载状态
   - 用户友好的错误提示

已修复的代码质量问题

1. 硬编码问题：
   - ✅ 移除硬编码的数据库密码
   - ✅ 使用环境变量配置
   - ✅ 提取魔法数字为常量

2. 重复代码：
   - ✅ 统一数据库连接管理（`db_connection.py`）
   - ✅ 统一日志记录（`user_logging.py`）
   - ✅ 统一错误处理模式

3. 命名不一致：
   - ✅ 统一使用`account`替代`username`
   - ✅ 统一字段命名规范

4. 性能优化：
   - ✅ 延迟加载AI模型（减少启动时间）
   - ✅ 数据库索引优化
   - ✅ 图片懒加载

部署与运维

环境要求

- Python 3.7+
- Node.js 16+
- MySQL 5.7+
- 至少2GB内存

部署步骤

1. 安装依赖：
python install_dependencies.py

2. 初始化数据库：
python database_files/run_init_schema.py

3. 配置环境变量：
创建`.env`文件，配置数据库和API密钥

4. 启动服务：
Windows
start_dev.bat

Linux/Mac
./start_dev.sh

监控与日志

- 访问日志：存储在`user_access_logs`表
- 错误日志：后端控制台输出
- 数据统计：管理员数据大屏

备份策略

1. 数据库备份：
   - 定期备份MySQL数据库
   - 建议每日备份

2. 文件备份：
   - `crawled_images/`：爬虫图片
   - `AIGC_graph/`：AIGC生成图片
   - `FrontEnd/public/`：用户头像

性能优化建议

1. 数据库优化：
   - 定期清理历史日志数据
   - 优化慢查询
   - 使用连接池

2. 缓存策略：
   - 考虑使用Redis缓存热点数据
   - 静态资源使用CDN

3. 图片优化：
   - 压缩大图片
   - 使用WebP格式
   - 实现图片懒加载

常见问题排查

1. 数据库连接失败

检查项：
- MySQL服务是否运行
- `.env`文件配置是否正确
- 数据库用户权限

2. API请求失败

检查项：
- 后端服务是否运行（端口8000）
- API密钥配置是否正确
- 查看后端日志

3. 图片无法显示

检查项：
- 图片文件是否存在
- 文件路径是否正确
- 文件权限设置

4. AIGC功能异常

检查项：
- AI模型API密钥配置
- 网络连接是否正常
- 查看错误日志
